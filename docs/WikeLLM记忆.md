# WikeLLM 记忆

> WikeLLM 是本应用的「记忆层」。文档定义文件布局、scope 语义、读写协议
> 与跨域查询策略。
>
> 与 [架构设计.md](架构设计.md) / [服务层.md](服务层.md) 配套阅读。

---

## 1. 设计目标

| 目标 | 含义 |
|------|------|
| 人可读 | 每个 scope 都是一个 Markdown 文件,人可直接打开阅读 |
| 可迁移 | 整个 `.vex/memory/` 目录可整体拷贝到另一台设备继续使用 |
| 可二次加工 | Agent / 工具可直接 grep / 解析,无须特殊解码 |
| 与数据库互补 | SQLite 存「事实」(会话/消息),WikeLLM 存「提炼后的清晰数据」 |

---

## 2. 文件布局

```
<root>/.vex/memory/
├── profile.md                  个人画像(整段覆盖)
├── short_term.md               短期记忆(滚动 N 天)
├── long_term.md                长期记忆(仅追加)
└── history/
 └── 202608/                 按年-月分组
        ├── 20260823.md       当日所有对话的清晰化摘要(每会话一段)
        ├── 20260824.md
        └── ...
```

`<root>` 通过 `path_provider.getApplicationDocumentsDirectory()` 获取;
与配置文件 [技术选型.md § 5.1](技术选型.md) 一致。

---

## 3. Scope 语义

| Scope | 文件 | 写入语义 | 读取语义 |
|-------|------|----------|----------|
| `profile` | `profile.md` | 整段覆盖 | 整段读取 |
| `short_term` | `short_term.md` | 追加 + 时间戳;超过 7 天自动滚动清理 | 最近 N 天 |
| `long_term` | `long_term.md` | 仅追加(每条带时间戳) | 全文 |
| `history` | `history/yyyymm/yyyymmdd.md` | 每会话一段(标题 + 时间 + 摘要 + tags) | 按日期或关键字 |

> **会话和消息的真实数据仍在 SQLite**;WikeLLM 仅承担「从对话中提炼出的清晰化记忆」。

## 4. 各文件格式

### 4.1 `profile.md`

```markdown
# Profile

- 称呼:小明
- 职业:后端工程师
- 偏好语言:中文 / Python
- 时区:Asia/Shanghai
- ...

<!-- auto-generated by WikeLLM @ 2026-08-23T10:30:00Z -->
```

### 4.2 `short_term.md`

```markdown
# Short Term

## 2026-08-23
- 10:30 [conv-uuid] 用户提到在重构 vex_owl_app 的状态层
- 14:12 [conv-uuid] 用户问过 Python 的 asyncio 入门

<!-- rolling window: keep last 7 days -->
```

### 4.3 `long_term.md`

```markdown
# Long Term

- 2026-08-23 用户对 Flutter 状态管理有深入兴趣,正在调研 Provider / Riverpod 选型
- 2026-08-20 用户反馈过「希望对话首轮结束后自动起名」,采纳并加入 v1.1

<!-- append-only -->
```

### 4.4 `history/yyyymm/yyyymmdd.md`

```markdown
# 2026-08-23

## [Flutter 状态管理选型] conv=abc123 round=3 14:30
- 关键摘要:用户对比 Provider / Riverpod / Bloc,倾向 Riverpod
- 关键问题:family/autoDispose 用法
- 已解决:✅

## [Android 16KB 适配] conv=def456 round=2 16:05
- 关键摘要:NDK r28 引入压缩策略
- 已解决:✅
```

## 5. 写入触发点

| 事件 | 写入位置 | 来源 |
|------|----------|------|
| 单轮对话结束 | `short_term` + `history/yyyymm/yyyymmdd.md` | `ChatService.send` 完成 |
| 用户画像更新 | `profile` | `ChatService` 抽取 + 用户手动 |
| 用户明确表示「记住这个」 | `long_term` | `ChatService` 检测关键字 |
| 删除会话 | `history/yyyymm/yyyymmdd.md` 标记 `已删除` | `SessionService.delete` |

## 6. 读取 / 查询协议

### 6.1 `MemoryService.buildContextPrompt(conversationId)`

> 给 Agent 当上下文,组合 profile + 最近 short_term + 当月 history。

```
[Profile]
<profile.md 内容>

[Short Term · 最近 7 天]
<short_term.md 内容(过滤 7 天内)>

[History · 当月]
<history/yyyymm/*.md 内容(本月全部)>

[Current Conversation]
title: ...
round: N
```

### 6.2 `MemoryQueryTool`

参数:`scope(profile|short_term|long_term|history)`,`keyword`。

- `profile`:整段匹配关键字。
- `short_term`:行级匹配,返回命中行 + 日期。
- `long_term`:全文匹配。
- `history`:跨月匹配 `history/yyyymm/yyyymmdd.md`,按日期倒序。

### 6.3 `HistoryQueryTool`

参数:`date(yyyy-mm-dd|yyyy-mm|空)`,`keyword`。

- `date` 给定 → 只查该(天|月)文件。
- `keyword` 给定 → 行级匹配;返回 `[date] conv=xxx summary=...`。
- 两个都给 → 交集。

---

## 7. 跨域策略(与 SQLite 协同)

`HistoryQueryTool` 需要回答「某次会话的实际原文」时:

1. 先查 WikeLLM `history/` 找到 `conv=xxx` 行。
2. 命中后再去 `ConversationRepository.loadMessages(conv)` 拉真实消息。
3. 合并返回给 Agent。

> WikeLLM 不复制消息原文,只记标题 + 摘要;原消息仍在 SQLite。

---

## 8. 并发与一致性

- WikeLLM 写入串行化:每个文件一个 `Future` 队列(内部用 `Completer` 链),避免同一进程并发写同一文件。
- 写入失败不阻塞对话:仅写日志,UI 不感知。
- 读取始终是「最新落盘内容」;不缓存(成本可忽略)。

---

## 9. 迁移 / 备份

整个 `<root>/.vex/` 可整体拷贝即视为「应用数据备份」:

```
.vex/
├── owl_setting.json   配置
└── memory/             WikeLLM
```

恢复:放回 `<root>/.vex/` 即可,重启后服务层自动加载。
