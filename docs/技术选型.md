## 2. 关键选型理由

### 2.1 状态管理:Riverpod(选),不选 Provider / Bloc

| 候选 | 优势 | 劣势 | 结论 |
|------|------|------|------|
| **Riverpod** | 无 BuildContext 依赖、易测试、原生支持异步流、Provider 升级版 | 学习曲线略陡 | ✅ 选用 |
| Provider | 简单、社区大 | 依赖 BuildContext、异步流支持弱 | ❌ |
| Bloc | 模式严谨、易测试 | 样板代码多、流式响应场景偏重 | ❌ |
| GetX | 一体化(状态/路由/DI) | 反向依赖多,污染架构 | ❌ |

**理由**:流式响应(AI 打字机)天然契合 Riverpod 的 `StreamProvider`,且后续扩展多 Agent 时,Riverpod 的 `family` / `autoDispose` 能优雅管理多个会话的状态。

### 2.2 HTTP:dio(选),不选 http / chopper

**理由**:dio 自带流式响应(`ResponseType.stream`),与 AI 的 SSE 流完美契合;拦截器可用于统一注入 `Authorization`、记录日志、429 重试。

### 2.3 Agent:自写 FastQaAgent(选),不引入第三方 Agent SDK

| 候选 | 优势 | 劣势 | 结论 |
|------|------|------|------|
| **自写 FastQaAgent** | 完全可控,无外部依赖;与 docs §3.4 设计直接对齐 | SSE / tool_calls 解析需要自己写 | ✅ 选用 |
| agentlib(Neul Labs) | 移动原生 Agent SDK,API 完整 | **pub.dev 上实际未发布**,依赖不可达 | ❌ |
| LangChain / Mastra | 生态成熟 | Python / TypeScript,与 Flutter/Dart 不兼容 | ❌ |
| Claude Agent SDK / OpenAI Agents SDK | 官方 SDK | Python / TypeScript,需要 Node/Python 运行时,iOS/Android 沙盒内不可用 | ❌ |

**理由**:v1.x 我们需要把 SSE 转译成 `AgentEvent`,涉及的工程量可控;dio 流 + 自写 SseParser + 自写 AiProvider + FastQaAgent 工具循环,代码量约 600 行,且零外部 Agent 依赖。

### 2.4 数据类:手写 `fromJson/toJson` + `Map`,不引入 freezed / json_serializable

**理由**:v1.x 数据类数量不多(Conversation / Message / OwlConfig / MemoryDoc / ToolDefinition 等),
手写 `fromJson` / `toJson` 即可,避免 freezed 引入 build_runner 复杂度;
WikeLLM 是 Markdown 文件,不依赖 JSON 序列化。
**取消先前选型 freezed + json_serializable**。

### 2.5 路由:go_router

**理由**:Flutter 官方推荐的声明式路由;支持深链接(后续桌面端/Web 端复用同一套路由)。

## 3. 不引入的依赖(显式拒绝)

| 候选 | 拒绝理由 |
|------|----------|
| `flutter_bloc` | 样板代码与流式场景不匹配 |
| `get` | 一站式框架会反向绑架架构,违背"小而美"原则 |
| `shared_preferences` | 配置文件走 `.vex/owl_setting.json`,不用 KV 库 |
| `flutter_secure_storage` | API Key 是用户在自己设备上配置的,无需额外加密层(后续可加) |
| `flutter_local_notifications` | v1.x 不在后台,无需通知 |
| `dio_cache_interceptor` | v1.x 不缓存 AI 响应 |
| `drift` / `sqflite` / `hive` | v1.x 会话/消息直接存内存 + WikeLLM 摘要,v2.x 再评估迁移到 SQLite |
| `freezed` / `json_serializable` / `build_runner` | 避免 codegen 依赖,v2.x 评估 |
| `agentlib` | pub.dev 实际不可达,见 §2.3 |

## 4. 模型协议(AI 调用层)

采用 **OpenAI 兼容 Chat Completions API**(因为 minimax 的 OpenAI 兼容端点)。

**请求示例**:

```json
POST {baseUrl}/v1/chat/completions
Authorization: Bearer {apiKey}
Content-Type: application/json

{
  "model": "minimax-M3",
  "messages": [
    {"role": "system", "content": "你是 灵枭,一个简洁的本地 AI 助手。"},
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "..."}
  ],
  "tools": [...],
  "stream": true
}
```

**响应(SSE)**:

```
data: {"id":"chatcmpl-xxx","choices":[{"delta":{"content":"你"},"index":0}]}
data: {"id":"chatcmpl-xxx","choices":[{"delta":{"content":"好"},"index":0}]}
data: [DONE]
```

**实现**:由 `OpenAICompatibleProvider` 调用 dio,
然后 `response.data.stream` 转 `Stream<String>`,经过 `SseParser` 解析为 `Stream<AiDelta>`,
最终在 `FastQaAgent` 中转译为 `Stream<AgentEvent>`。

## 5. 文件与目录

### 5.1 配置文件:`<root>/.vex/owl_setting.json`

- `<root>` 通过 `path_provider.getExternalStorageDirectory()` 获取
- 路径:`<root>/.vex/owl_setting.json`(Android 11+ 需在 `AndroidManifest.xml` 申请 `MANAGE_EXTERNAL_STORAGE` 或回退到应用专属目录 `<root>/Android/data/<pkg>/files/.vex/`)
- **写入策略**:仅在用户主动保存时写盘;启动时若文件不存在 → 写默认配置

### 5.2 WikeLLM 记忆:`<root>/.vex/memory/`

- `profile.md` / `long_term.md` / `short_term.md` / `history/yyyymm/yyyymmdd.md`
- 由 `MemoryService` 负责串行写与读

### 5.3 会话与消息:v1.x 内存版 + WikeLLM 索引

- 会话 / 消息 / 工具调用轨迹:内存(`SessionRepository` 内存实现),应用退出即丢失;
- 摘要化历史:写入 WikeLLM `history/yyyymm/yyyymmdd.md`,可长期保留;
- **v2.x 迁移**:评估 Drift / SQLite,把会话与消息持久化。

## 10. 一句话总结

> **flutter_riverpod + go_router + dio + path_provider + intl** 构成 v1.x 的核心依赖,
> 自写 FastQaAgent + SseParser + OpenAICompatibleProvider 接管 AI 流式与工具调用,
> WikeLLM 负责记忆层,会话/消息 v1.x 走内存,v2.x 评估 Drift 持久化。
