# 架构与模块划分

> 本文档定义 v1.0 的代码组织、分层关系与核心数据流。与 [README.md](../README.md)、[UI设计.md](UI设计.md)、[技术选型.md](技术选型.md) 配套阅读。

---

## 1. 设计目标

| 目标 | 含义 |
|------|------|
| 业务为核心 | UI 不直连数据源;Agent 不感知页面 |
| 易扩展 | v1.x → v2.x 增加多 Agent / 多 Provider 时,改动收敛在 `core/agent` 与 `core/provider` |
| 可测试 | Repository / Service / Agent 不依赖 Flutter Widget,可纯 Dart 单测 |
| 离线优先 | 配置文件 / 历史 / 配置均在本地;网络只是"对话内容"的来源 |

## 2. 分层架构

```
┌────────────────────────────────────────────┐
│  Presentation (UI)                         │  ← Flutter Widget / Page
│  ├─ pages/                                 │
│  ├─ widgets/                               │
│  └─ state/ (Riverpod providers)            │
├────────────────────────────────────────────┤
│  Application (业务编排)                    │  ← Controller / UseCase
│  ├─ chat/                                  │
│  ├─ conversation/                          │
│  └─ settings/                              │
├────────────────────────────────────────────┤
│  Core (领域)                                │  ← 业务实体 / Agent / 仓库接口
│  ├─ agent/                                 │
│  ├─ model/                                 │
│  ├─ repository/                            │
│  └─ event/                                 │
├────────────────────────────────────────────┤
│  Infrastructure (基础设施)                 │  ← 具体实现
│  ├─ http/ (dio + AI provider)              │
│  ├─ db/ (Drift + migrations)               │
│  └─ storage/ (path_provider + .vex 配置)   │
└────────────────────────────────────────────┘
```

**依赖方向**:上层依赖下层,下层不知道上层存在。所有跨层调用通过**接口 + 注入**(Riverpod `Provider`/`FutureProvider`)。

## 5. 核心接口

### 5.1 `Agent`

```dart
abstract class Agent {
  String get id;          // 'fast-qa'
  String get displayName; // '快速问答'

  /// 流式调用,返回 assistant 完整回复 + 元数据
  Stream<AgentStreamEvent> chat({
    required Conversation conversation,
    required List<Message> history,  // 已压缩 / 未压缩的消息
    required String userInput,
    required OwlConfig config,
  });
}

sealed class AgentStreamEvent {
  const AgentStreamEvent();
}
class AgentDelta extends AgentStreamEvent { final String text; }
class AgentCompleted extends AgentStreamEvent {
  final String fullText;
  final TokenUsage usage;
}
class AgentFailed extends AgentStreamEvent { final Object error; }
```

### 5.2 `AiProvider`

```dart
abstract class AiProvider {
  Stream<String> streamChat({
    required String model,
    required List<Map<String, String>> messages,
    required String baseUrl,
    required String apiKey,
  });
}
```

### 5.3 `ConversationRepository`

```dart
abstract class ConversationRepository {
  Stream<List<Conversation>> watchAll();
  Future<Conversation> create();
  Future<void> rename(String id, String newTitle);
  Future<void> delete(String id);
  Future<void> appendMessage(Message msg);
  Future<void> compressHistory(String conversationId, String summary);
  Future<List<Message>> loadMessages(String conversationId);
}
```

### 5.4 `ConfigRepository`

```dart
abstract class ConfigRepository {
```

## 6. 关键时序

### 6.1 启动

```
main()
  ↓ runApp(ProviderScope(child: OwlApp()))
OwlApp.initState()
  ↓ override providers
  ├─ configRepositoryProvider = FileConfigRepository()
  ├─ conversationRepositoryProvider = DriftConversationRepository()
  └─ aiProviderProvider = OpenAiCompatibleProvider()

SplashPage.initState()
  ↓ ref.read(initProvider)        ← FutureProvider 启动时执行一次
    ├─ configRepository.load()    ← 读 .vex/owl_setting.json
    ├─ conversationRepository.init()  ← Drift open
    └─ 决策路由(首次 → ChatPage,否则 → HomePage)
```

### 6.2 发送消息

```
ChatPage 提交 → ref.read(chatControllerProvider.not).send(userInput)
        ↓
ChatController.send(userInput)
  ├─ 立即 push 用户消息到 state(乐观更新)
  ├─ conversationRepository.appendMessage(userMsg)
  ├─ AgentRegistry.current.chat(...).listen(
  │     onData: (delta) → state.append(delta)
  │     onDone:  (completed) → emit ConversationCompletedEvent
  │     onError: (e) → state.setError(e)
  │   )
  └─ EventBus.fire(ConversationCompletedEvent(...))
        ↓
ConversationRepository 监听 EventBus
  └─ 自动写入最终 assistant 消息 + 增加 round + 更新会话标题
```

### 6.3 保存配置

```
SettingsPage 保存按钮
  ↓ ref.read(settingsController.not).save(newConfig)
SettingsController.save()
  ├─ OwlConfig.validate(newConfig)
  ├─ configRepository.save(newConfig)
  ├─ SnackBar 成功
  └─ EventBus.fire(ConfigChangedEvent)
```

## 7. 事件总线

```dart
class EventBus {
  final _ctrl = StreamController<AppEvent>.broadcast();
  Stream<T> on<T extends AppEvent>() =>
      _ctrl.stream.where((e) => e is T).cast<T>();
  void fire(AppEvent e) => _ctrl.add(e);
}
```

| 事件 | 订阅者 | 行为 |
|------|--------|------|
| `ConversationCompletedEvent` | ConversationRepository | 持久化、轮次 +1 |
| `MessageAppendedEvent` | Settings 页(可选) | 统计 token |
| `ConfigChangedEvent` | App 全局 | 失效 AiProvider 缓存 |
| `ConversationDeletedEvent` | UI | 从列表移除 |

## 8. 错误处理策略

| 错误类型 | UI 表现 | 重试策略 |
|----------|---------|----------|
| 网络超时 | AI 气泡显示"网络超时" + 重试按钮 | 用户手动 |
| 401 / 403 | "鉴权失败,请到设置检查 API Key" | 不重试 |
| 429(限流) | "请求过于频繁,5 秒后自动重试" | 退避重试 |
| 流中断 | "响应被中断" + 已收到的内容保留 | 用户手动 |
| 配置缺失 | 拦截发送 → 引导到设置页 | 不重试 |

## 9. 安全与隐私

- API Key 写入用户可读的 `.vex/owl_setting.json`(明文)。**用户在共享设备时需自负责任**——后续版本可叠加 `flutter_secure_storage`。
- 不收集任何遥测数据(`flutter run --no-analytics`)。
- 网络请求只发往用户配置的 `baseUrl`,无任何额外上报端点。

## 11. 一句话总结

> **四层架构 + 接口注入 + 事件总线**:UI 渲染、业务编排、领域逻辑、基础设施彻底解耦,Agent 不知道有 UI,Repository 不知道有 Page,扩展多 Agent / 多 Provider 时改动局限于 `core/agent` 与 `data/http/`。
